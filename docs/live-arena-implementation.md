# 直播导演 · AI 实战演练实施计划

## 审计

- 旧 `/live` 装配 `getLiveView`。升级复用摄像头预览、浏览器语音模式、现有场次口播、商品列表与服务端模型配额。`/live` 现在只呈现实战演练，旧彩排页面与专用操作已移除，既有场次与资料不删除。
- 旧问题依赖定时/手工录入，整场口播与问题合并评分，没有角色短期记忆、按题证据、追问因果、态势指标或同类训练对照。新训练采用独立状态机和证据评分，不改写旧报告。
- 商品档案提供价格、规格、产地、保存和保质期；Product DNA 与品牌档案有确认状态；可按商品、平台和口播类型读取素材。现有 RAG 按商户范围查切片，带引用门槛；新模式采用进场前由商户复核的**有界资料快照**，不把系统生成的知识摘要、未确认 DNA 或文案作为事实。
- 复用 `AIProvider.generateObject`、Zod、DashScope、已有计量和权限，不改 Provider、其他 Agent 与业务编排；复用知识缺口入口。模型只读取当前题、少量相关资料和本次回答，不接收摄像头视频。失败明确反馈，不伪造模型结果。
- 复用 `getSessionContext` 派生商户，服务端校验所有入口。Mock 新记录也按商户隔离，不作为生产库。

## 实施阶段

1. `src/lib/live-arena/{types,engine,report}.ts`：状态/事件/分数；添加 `0014_live_arena.sql`、schema/journal 和 `repositories/live-arena.ts`，两种持久库与 Mock 提供一致的版本比较写入。
2. `services/live-arena.service.ts`、`ai/agents/arena-answer.ts`：受限语义判断，核对快照与引用；短租约限制并发，失败可重试、迟到结果丢弃。
3. `actions/live-arena.ts`、`components/live/arena-*.tsx`、`app/(app)/live/page.tsx`：备播、互动、语音、趋势、恢复。采用轻量事件触发，不引入 WebSocket。
4. 规则加语义的复盘、专项复练、按题比较、知识缺口确认和内容运营入口；不自动修改商品事实。
5. `tests/live-arena.test.ts` 及隔离数据验证、浏览器演示与边界记录。

实战演练仅新增 `0014_live_arena` 表；下线旧页面不另加迁移，也不删除旧表。回滚可部署旧代码保留新表。远程执行迁移后再发布，PGlite 由启动钩子执行。不要用现有数据库做试验。

## 已实现的数据流

1. 备播读取当前商户的商品字段、商品专属或店铺级人工物流/售后文档。优先商品专属文档；每类最多两份，每份保留开头 480 字。品牌与卖点只用已确认版本；已有口播仅供参考。页面展示缺项，开始时再校验资料摘要版本。产品名称、输入和来源不经 URL 传给第三方。
2. `live_arenas` 保留每场配置、商户键、版本、资料、按题文字、观众状态、关键事件和最终报告。行更新用 CAS（按商户、记录和版本比较更新）；局部唯一索引保证同一商户仅一场未结束。开始与提交使用客户端请求 ID 去重。分析前写草稿和短租约；过期可重试。取消/暂停/结束清除租约并让迟到结果不能提交；同进程和浏览器断开时也会尝试取消运输层调用。跨进程无法保证已发出的供应商请求立刻停止或退费。
3. 初问来自目标；后续结合不同角色的主题偏好、兴趣、未解决顾虑和资料覆盖度安排。部分核验后只追问剩余项；乱答追问原顾虑；疑似不实承诺要求核对。高压开两题，启用干扰角色时两题等待 20 秒可插话一次。每场最多 16 道模拟问题、32 次核验尝试。模拟认可度取角色信任均值；有效回应率取完整/部分回答数除以已发问题数；关键事件会记录当时数值及触发理由。
4. 文字提交通过同源 JSON route，以免长模型调用占住暂停和取消的 Server Action 队列。页面每 6 秒同步轻量状态，无常驻连接。刷新可恢复服务端已提交的稿件和结果；输入框中尚未提交的文字不持久化。
5. 工作台六岗位协作仍能生成备播建议。结果链接进入同一个 `/live`，只读展示指定建议和引用，并预选商品（有进行中的演练时先保留当前场次）。备播建议不计入主播作答或评分。

## 核验、评分与复练

- `AI_PROVIDER=mock` 使用可复现规则，不发模型请求。真实模式每次显式提交最多做一轮结构化语义核验，使用现有供应商超时和商户配额；不会因每个转写字、弹幕、刷新或结束而调用模型。正常的网络层重试仍按既有配置计量。
- 语义判断必须通过 Zod；引用只允许本次提供的资料 ID，而且回答原话和来源摘录必须存在，数字有额外比对。规则标出的无依据承诺优先于语义判断。规则不能穷尽所有说法，资料一致性也不等同于食品安全、物流真实性或合规证明。人工相互冲突的资料应先核对，不用于确认真实承诺。
- 权重集中在 `ARENA_WEIGHTS`：事实 25、异议 25、卖点 20、控场 20、表达 10。事实用命中引用和待核风险计数；异议只比较各首问；卖点按确认条目覆盖率；控场用规定时窗内提交比例；表达用规则/语义的清晰度判断。无证据的分项不可评估，综合按可评项归一。报告留存原话、题目、来源链接、风险、建议和缺项。
- 复练沿用商品、难度、角色及弱项挑战。报告并排展示同类首问的原话和核验级别；资料版本或核验方式不同，不推断进步。商品资料更新时，重新打开报告会提示快照过期。
- 用户确认后可将缺项写入答疑助手的知识缺口；不会改动商品资料。话术入口预选商品、口播格式与内容角度，生成及覆盖仍走推广素材页的用户确认流程。

## 三分钟演示

1. 用测试商户创建商品（例如演示鲍鱼：500g、60 元/盒、产地连江），不必捏造物流时效。先用 `DATA_SOURCE=local` 加 `AI_PROVIDER=mock` 演示，不需要外部模型或语音权限。
2. 登录 → **直播导演**（`/live`）。选商品、价格异议、进阶、3 分钟；检查资料、勾选核对、开始。先回答「这款规格是 500 克」，观察认可度变化和针对每盒价格的追问。
3. 结束 → 展开首问证据 → **根据弱项再次训练**。回答「这款规格是 500g，每盒 60 元，请按每份规格和售价比较」→ 结束。核对两次原话及同类回应等级，不能把更高分当作真实成交改善。
4. 加演：高压模式开启多个角色后让两条问题等待，观察插话和问题绑定；品质质疑场里试答「保证 24 小时内到货」，确认无依据时显示待核。语音或镜头不可用时继续打字。

真实模型演示时更改服务端配置为 `AI_PROVIDER=dashscope`，使用有效密钥、已登录的持久化商户和非零额度。先在测试商品上试一次；与供应商共享的内容为当前题、相关档案片段和提交文字，不含视频。真实模型未在本次验证中联网调用。

## 验证记录与剩余边界

- `pnpm typecheck`、`pnpm db:check`、`pnpm build`、`pnpm test` 通过，27 项用例中 15 项覆盖直播演练。测试包含 PGlite 迁移、角色与事件因果、规则复现、引用与计价单位校验、模型失败、取消写入、按商户隔离、工作台建议深链和复练；生产构建使用 Mock 配置。
- `pnpm test:arena:browser` 使用隔离 PGlite、合成商品和无头 Edge，检查主入口备播、部分回应、追问、模拟摄像头权限拒绝、暂停刷新恢复、证据复盘、专项比较、窄屏无横向溢出，以及旧模式链接不会打开旧彩排。运行时设置 `BUDDY_SMOKE_BROWSER` 为本机 Edge/Chrome 可执行文件路径，预留本机 3917 端口，并避免同时占用同一开发构建缓存。
- 未实测真实麦克风识别、供应商模型效果和远程 PostgreSQL 部署。浏览器 ASR 依赖设备、权限和浏览器识别服务；语音转写只提供段落草稿，用户确认后提交。模型/规则判断不是人工质检，也不评价声音或镜头表现。Mock 旧业务仍共享演示目录，但新训练记录按账号隔离、重启即丢。
