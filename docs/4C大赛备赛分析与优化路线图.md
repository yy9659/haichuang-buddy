### 真实存在的技术亮点（不是表面功夫）

以下均有代码级证据，答辩时可直接打开源码演示：

1. **真 DAG 多 Agent 编排**（全项目最强项）
   - `src/ai/workflows/executor.ts`：真实调度循环，`while` 扫描待启动任务 → 并发上限 3 → 依赖检查 → `Promise.race` 收尾；含超时中断、失败向下传播（`dependency_failed`）、成果复用判定。
   - `dependency-graph.ts`：真 Kahn 拓扑排序 + 成环检测。
   - `plan-validator.ts`：三色 DFS，能报出**环的具体路径**；11 种违规码含跨字段语义校验。
   - `business-brain.service.ts` 的 `createTaskRunner()` 真实调用 6 个 Agent Service，两层纠错（Schema 层 + 计划合法性层）最多 2 轮。

2. **真向量 RAG**（不是关键词匹配）
   - `src/rag/retriever.ts` 真调 `provider.embed()`；hybrid 打分 = 余弦相似度 + 词面覆盖度 + 知识优先级。
   - 阈值按 Provider 分两档（real / mock），检索不足即转人工并记录知识缺口。
   - `src/rag/citations.ts` 的 `validateCitations()` **拒绝伪造引用**（chunkId 必须来自本次检索结果）。

3. **Provider 抽象质量高**
   - 未知 provider 明确报 `NOT_IMPLEMENTED`，**绝不静默降级到 Mock**。
   - Zod 结构化输出 + 回喂纠错；只有 `SCHEMA_INVALID` 才重试，传输/鉴权/限流错误立即透传。
   - HTTP 错误码归一化、欠费识别、超时与 AbortSignal 穿透、SSE 流式解析。

4. **安全工程扎实**（超出学生作品平均水准）
   - scrypt 密码哈希 + `timingSafeEqual`；32 字节 CSPRNG 会话 token，**库里只存 SHA-256**。
   - 登录**时间侧信道防护**：账号不存在时也跑一次假哈希。
   - **会话级多租户隔离**：请求内无有效会话绝不回落到第一个租户。

5. **代码整洁**：全项目 `TODO/FIXME/@ts-ignore/eslint-disable` 零命中。

## 三、核心问题：定位错位

这是最重要的一节。你 10 月准备的《创业项目计划书》是给**连江县首届创新创业大赛（赛道二 HAI+OPC）**的。4C 的评审逻辑完全不同：

| 对比项 | 创业赛（已准备） | 4C 软件应用与开发（现在要打） |
| :-- | :-- | :-- |
| 核心问题 | 这生意能不能成？ | 这个软件做得怎么样？ |
| 关键证据 | 访谈、付费意愿、财务测算 | 公网可运行、源码、测试报告、设计文档 |
| 主打维度 | 应用价值、市场前景 | **系统设计 30% + 功能效果 30%** |
| 商业模式 | 必答重点 | 属"应用价值"一栏，非核心 |
| 财务/融资 | 独立一章 | 基本不考 |

### 4C 评分权重（省赛通行标准）

| 一级指标 | 权重 | 二级要点 |
| :-- | :-- | :-- |
| 作品创意 | 20% | 设计理念、技术创新、功能特色 |
| 功能效果 | 30% | 需求分析、功能实现、应用价值 |
| 技术实现 | 30% | 系统设计、**数据库设计**、系统实现、**代码质量**、**工具种类** |
| 作品呈现 | 10% | 运行效果、人机交互、现场答辩 |
| 作品文档 | 10% | 必交文档、文档结构 |

（中南赛区另有"创/量/健/技/美"各 20% 的口径，要素一致。）

### 4C 的硬性资格约束（必须逐条核对）

1. **Web 类必须部署到公网可访问的服务器**（安徽、中南赛区明文要求，未提供视为资格审查不通过）。
2. **AI 工具必须在组委会指定的 15 款国产工具内**：阿里通义系列、百度文心、DeepSeek、稿定设计、ModelWhale、即梦/豆包、讯飞星火、Kimi、腾讯混元、智谱 AI。
   - ✅ 你用的 **通义千问 + 通义万相属"阿里通义系列"，合规**。这一点要在文档里显式写明，是加分项不是风险。
3. **作品须在本届窗口内原创**：第 19 届窗口为 2025.7.1–2026.6.30，你备的是**第 20 届**，窗口约 **2026.7.1–2027.6.30**；项目首次提交 2026-09-25，**在窗口内**。
4. **队伍 2–5 名同校本科生，指导教师 ≤2 名**；国赛现场答辩作者不少于 2 人。
5. **一稿多投核查**：若本项目已在连江创业赛参赛/获奖，需向组委会确认 4C 是否允许，并在材料中如实说明；不得作为"前期作品雷同"重复参赛。**这是需要提前问清楚的风险点。**

## 四、优化路线（按优先级）

### 第 0 优先级：三条资格/地基线（不做则一切归零）

**A. 公网部署上线**
- `DATA_SOURCE` 必须切到 `db`（PGlite 依赖本地文件系统，无法用于 Serverless）。
- 建 PostgreSQL（Supabase 免费档即可）+ 跑迁移 + seed + 建演示账号；**开启 pgvector 扩展**（顺手解决 RAG 索引问题）。
- 部署目标建议**国内可访问**的云服务器（腾讯云/阿里云轻量 + pm2/Docker），境外托管可能访问慢或被墙。
- 产出：《公网部署实录》（服务器配置、域名、HTTPS、迁移命令、常见故障）。

**B. 恢复测试套件**
- 从 `.data/development-archive-20261006/` 恢复 `vitest.config.mts`、`vitest.db.config.mts`、`eslint.config.mjs` 与全部 `*.test.ts`。
- `package.json` 补 `lint` / `test` 脚本；`ci.yml` 增加 lint + test 步骤（当前是有外壳无门禁）。
- 产出：**《软件测试报告》**——功能用例表、性能用例（关键接口响应时间）、兼容性用例（Chrome/Edge/Firefox、桌面/移动、深浅色）。

**C. 文档体系重写（4C 口径）**
- 设计说明书、用户手册、部署运维文档、作品信息概要表四件套。
- 叙事从"能赚钱"切换为"技术难在哪、创在哪"。

### 第 1 优先级：技术纵深（喂给"技术实现 30%"）

1. **RAG 升级为真向量索引 + 检索评测报告**
   - 引入 pgvector（HNSW/IVFFlat），把全表扫描换成 ANN 索引。
   - 建 50–100 条检索评测集，输出 **Recall@K / MRR / 延迟** 对比表（全表扫描 vs HNSW）。
   - 这是"算法优化"的**硬证据**，同时充实测试报告。投入小、回报极高。

2. **Agent 可观测性与成本看板**
   - 在已有 `/admin/monitor` 基础上升级：每个工作流的 **Agent 调用链路图**（谁调了几次模型、耗时、token、成本）、失败率、成果复用率。
   - 差异化亮点，答辩时直接呼应"多 Agent 协作"核心卖点，也体现"工具种类/深度整合"评分点。

3. **模型路由与降级策略**
   - 按任务复杂度路由到不同档位模型（快/便宜 vs 强/贵），主模型失败自动降级到备用。
   - 指标：成本下降 X% 而质量不降。
   - **直接命中 4C 的评审焦点**："考核作者运用、组合和优化 AI 工具以解决实际问题的能力"。

### 第 2 优先级：功能创新（喂给"作品创意 + 功能效果"）

4. **多模态增强**：商品图理解已有基础，补"拍照/手写销售单 OCR 录入"（已有 Excel/CSV 导入，OCR 是自然延伸）。演示效果直观。
5. **知识缺口闭环 2.0**：从客服对话/直播评论自动聚类高频问题 → 一键生成"待补知识卡" → 商户确认入库 → 回流检索。叙事："越用越懂这家店"。
6. **主题切换 + 无障碍**：补深浅色切换（部分信创赛项明确要求深色模式适配）。

### 第 3 优先级：锦上添花（视时间，注意别做成四不像）

7. 图文成片 / 短视频分镜建议（契合直播电商方向，但较重）。
8. 多租户 SaaS 运营看板强化。

## 六、答辩与呈现策略

1. **现场一定要跑真实模型**（DashScope），并准备降级预案（网络异常切 mock 演示模式，如实说明）。
2. **主推一个技术壁垒**：多 Agent DAG 编排。开场 30 秒讲清"为什么难"——不是顺序调用，而是有依赖、并发、超时、失败传播、成果复用的真实调度器，现场打开 `executor.ts` 佐证。
3. **选题锚定国家战略**：海产小商户数字化 → 乡村振兴/助农、中小企业数字化转型。这是 4C 一贯偏好的人文/社会价值叙事。
4. **主动交代边界**：客服/直播为站内模拟、无真实商户效果数据。评审对"夸大"扣分远重于"诚实交代边界"。
5. **清理自伤项**：删除孤儿假数据组件 `business-metrics-card.tsx`，避免与项目"不伪造数据"纪律矛盾被点名。
